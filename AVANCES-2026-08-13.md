## 4. Hallazgo falso: mayúsculas en carpetas de imágenes

`GUIA-FUENTE.md` reportó como hallazgo que `public/images/projects/` tenía carpetas `EduCare/` y `Holomedicina/` en mayúscula mientras el contenido las referencia en minúscula, con riesgo de 404 en Vercel (Linux, case-sensitive).

**Es falso.** `git ls-files` muestra que el árbol de git siempre tuvo las rutas en minúscula: las escribió `keystatic-cloud[bot]` directamente así (commits `8c13c2f` y `4aca5a0`, 12/08). La mayúscula es un artefacto del filesystem local de Windows (`core.ignorecase=true`), invisible para git y para cualquier otro clon, incluido el de Vercel. No hay nada que arreglar.

Se llegó a escribir dos pedidos sobre esto antes de que Code lo detuviera con evidencia. **El hallazgo 1 de `GUIA-FUENTE.md` debe considerarse desmentido.** Los otros cuatro hallazgos de ese documento siguen en pie.

## 5. Warning de Astro que describía mal su propia causa

El warning decía que `/en/` (archivo físico) perdía contra `/en` (ruta implícita del fallback i18n). Borrar el archivo físico —lo que el mensaje sugería— rompió el build: la página salió vacía. El archivo físico era el que hacía todo el trabajo; el fallback no prerenderizaba nada.

**Regla: un mensaje de warning describe un síntoma, no necesariamente su causa.** Verificar antes de actuar sobre lo que el mensaje insinúa.

Se optó por sacar el `fallback` (opción A) porque: era configuración muerta con diff vacío comprobado; cuando actúa sirve texto en español bajo una URL declarada `lang="en"`, que es peor que un 404 porque no se ve; y un warning permanente en cada build es el escondite del próximo warning que sí importe.

## 6. Reglas de proceso nuevas

1. **Un problema resuelto parcialmente se anota como deuda, no se cierra.** El 12/08 se borraron las imágenes cargadas a mano pero quedaron las carpetas; el residuo no se anotó y reapareció hoy como hallazgo nuevo, costando dos pedidos.

2. **Lo que se afirma sobre archivos se verifica contra `git ls-files`, no contra el disco local.** El disco de la máquina de trabajo y el árbol de git pueden no coincidir, y solo el segundo llega a producción.

3. **Los ejemplos de PARÁ en un pedido son ilustraciones de una categoría, no la lista de casos que califican.** Code descartó un PARÁ legítimo por no coincidir con los ejemplos textuales. Redacción corregida en todos los pedidos posteriores.

4. **Cada rama pusheada se cierra con una indicación explícita de merge o espera.** Un pedido se escribió asumiendo un merge que nunca se confirmó, y Code paró correctamente.

5. **Método de auditoría barato para CSS:** como `@source` limita el escaneo a `src/`, una `@utility` que no aparece en el CSS de `dist/` está muerta por definición.

6. **Control positivo antes de confiar en una búsqueda vacía.** Code verificó con `font-bitacora` (clase viva) que el método de grep encontraba algo, antes de concluir que las 4 utilidades no aparecían. Sin eso, "no hay nada" y "la herramienta no busca bien" son indistinguibles.
